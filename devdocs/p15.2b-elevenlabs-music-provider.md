# P15.2b — Real ElevenLabs Music provider

Builds on the P15.2a foundation (`7b09def`) by replacing the deferred ElevenLabs
music stub with a real, server-side adapter. No second music architecture: the
existing provider seam, service, storage, validation and security layers are
reused as-is.

## Design choices

- **Endpoint / transport.** `POST {baseUrl}/music?output_format=<code>` with the
  `xi-api-key` header and a JSON body. The API reference is authoritative:
  `output_format` is a **query** parameter (not a body field). Plain server-side
  `fetch`, no new SDK dependency. Default base URL
  `https://api.elevenlabs.io/v1` (residency endpoints supported via env).
- **Binary response.** The endpoint returns a file download, not JSON, so the
  adapter reads `arrayBuffer()` and persists the bytes through `mediaStore`.
  A JSON or empty body on a `200` is treated as an invalid response.
- **Model default `music_v2_5`.** Supported models are `music_v1`, `music_v2`,
  `music_v2_5`; anything else is rejected before any request. Overridable with
  `ELEVENLABS_MUSIC_MODEL`.
- **Prompt-based generation only.** `prompt` is required, trimmed, non-empty and
  capped (`MAX_MUSIC_PROMPT_LENGTH = 2000`; the API publishes no numeric prompt
  cap, so a conservative bound is enforced server-side).
- **`seed` is intentionally not sent.** The API forbids `seed` together with
  `prompt`. The service still stores the seed for traceability, but the adapter
  omits it from the request body.
- **`force_instrumental`** is always sent (the API only allows it with a prompt,
  which is always present), defaulting to `true`.
- **Output format.** Defaults to `mp3_44100_128` and only accepts MP3 codes.
  This keeps the stored asset extension/mime mapping unambiguous and avoids the
  lossless/high-bitrate downloads gated behind higher ElevenLabs tiers.
  Overridable with `ELEVENLABS_MUSIC_OUTPUT_FORMAT`.
- **Hard request deadline.** The caller abort signal is combined with a
  configurable timeout (`ELEVENLABS_MUSIC_TIMEOUT_MS`, default 300000 ms) so a
  stalled paid call cannot hang the request indefinitely.
- **Paid call only on explicit action.** The adapter is constructed lazily by the
  registry and performs no network I/O in its constructor. `generate()` is only
  invoked by `generateProjectMusic`, which is only reached from the explicit
  project-music API action. Render, composition, polling, startup, recovery and
  the mock provider never call it.
- **No automatic retries.** A single `fetch`; no retry loop, to avoid double
  billing.
- **Error mapping.** Distinct provider codes are surfaced with safe statuses:
  auth/insufficient rights -> `PROVIDER_AUTH` (502), rate limit/quota ->
  `PROVIDER_RATE_LIMIT` (429), validation/rejection -> `PROVIDER_REJECTED` (422),
  timeout/network/invalid body -> `PROVIDER_FAILED` (504/502). Missing key ->
  `NOT_CONFIGURED` (409) before any request.
- **No half-registered assets.** If the project update fails after the audio file
  is written, the file is removed and a clear `500` is returned, so no orphan
  asset is left behind.
- **Credentials.** Reuses `ELEVENLABS_API_KEY`, server-side only; the key is
  never echoed in logs, responses or errors.

## Changed files

- `lib/ai/music/elevenlabs-provider.ts` (new): the adapter, output/model
  resolution, error parsing (handles `detail: string | {message} | [{msg}]`),
  timeout/signal handling, binary persistence and duration probing.
- `lib/ai/music/registry.ts`: `elevenlabs` now returns the real provider instead
  of throwing `UNSUPPORTED`.
- `lib/generation/music-service.ts`: default model `music_v2_5`; provider error
  mapping extended with auth/rate-limit/rejected codes; orphan-file cleanup when
  the final project update fails.
- `tests/music-provider-registry.test.ts`: registry now resolves the real
  provider.
- `tests/music-elevenlabs-provider.test.ts` (new): mocked-fetch coverage.
- `tests/music-service.test.ts`: rate-limit mapping + orphan cleanup tests.

## Environment configuration

```
ELEVENLABS_API_KEY=<server-side key>            # required for real generation
ELEVENLABS_MUSIC_MODEL=music_v2_5               # optional (default)
ELEVENLABS_MUSIC_OUTPUT_FORMAT=mp3_44100_128    # optional (default)
ELEVENLABS_MUSIC_TIMEOUT_MS=300000              # optional (default)
ELEVENLABS_MUSIC_BASE_URL=https://api.elevenlabs.io/v1   # optional (residency)
```

## Remaining limits / out of scope

- **No UI.** There is currently no music panel in the workspace UI. The server
  adapter and the existing `POST /api/projects/[id]/music` action
  (`generate` | `regenerate` | `select` | `clear`) are the wired surface; a
  minimal prompt/duration/instrumental form with an explicit "generate" button
  still needs to be added. No generation happens on page open/render.
- Composition plans, inpainting, streaming and generation during render are out
  of scope.
- Lossless/high-bitrate (PCM/192 kbps) outputs are intentionally not exposed.
- Older MP3 errors return the raw provider message; secrets are never included.

## Manual test (one short track)

With `ELEVENLABS_API_KEY` set and real mode enabled:

```
curl -X POST "$APP/api/projects/<projectId>/music" \
  -H 'Content-Type: application/json' \
  -d '{"action":"generate","prompt":"calm ambient piano","musicLengthMs":15000,"instrumental":true}'
```

Expected: `200` with `status: "generated"`, a new `music` asset persisted under
the project, and `project.music.status === "generated"`.
