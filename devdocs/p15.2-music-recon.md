## 2. Official API and subscription findings

### 2.1 Music API (exact endpoint facts)
- Endpoint: `POST https://api.elevenlabs.io/v1/music`, JSON body, returns the audio file
  as a binary download. Regional hosts exist (us/eu/in/sg residency).
- Auth: same `xi-api-key` header scheme as TTS. Docs note the response includes a song ID
  in the headers (used later for inpainting/section sourcing).
- Query `output_format` (default `auto`): v1 default `mp3_44100_128`, v2 default
  `mp3_48000_192`. Allowed: mp3 (various), pcm up to 48k, ulaw/alaw, opus.
- Body:
  - `prompt` (string) OR `composition_plan` (mutually exclusive).
  - `music_length_ms` (3000..600000, only with `prompt`; if omitted the model chooses).
  - `model_id`: `music_v1` (default), `music_v2`, `music_v2_5`.
  - `seed` (not with prompt), `force_instrumental` (only with prompt),
    `finetune_id`, `respect_sections_durations`, `store_for_inpainting`,
    `sign_with_c2pa`.
  - `composition_plan` shapes differ by model family (v1 `MusicPrompt` with sections;
    v2/v2_5 `CompositionPlan` with chunks). Section durations 3s..120s; total up to 10min.
- Errors: 422 validation (list of `{loc,msg,type}`).
- Instrumental: `force_instrumental: true` guarantees no vocals (with `prompt`).
- Reproducibility: `seed` "can help achieve more consistent results, but exact
  reproducibility is not guaranteed".

### 2.2 Plan entitlements - CRITICAL distinction
The general ElevenLabs creative subscription and the **Eleven Music Commercial Rights
Table (Music Terms, Exhibit A)** are separate. A regular plan's generic "commercial
license" statement does NOT by itself grant every music right. Per Exhibit A, for the
**Starter** tier:
- Eligibility: **For Individual Use Only**.
- Monthly Generation Limit: **17 minutes**.
- Monthly Download Limit: **30 minutes**.
- Music Streaming Distribution: **Prohibited**.
- Media Rights: **all online and offline commercial use permitted, EXCEPT film, TV,
  radio, and Studio Games**.
- Model Resale: **Prohibited**. Music Library creation/distribution: **Prohibited**.
- Attribution: **No Attribution Required**.
- Concurrency Limits: **2**.
- High-Quality Downloads (lossless WAV or 192 kbps mp3): **No**.
- API Access: **Yes**.

Cross-checks:
- Pricing page: Eleven Music costs **900 credits per minute**; Starter = 30,000 credits/month.
  30,000 / 900 ≈ 33.3 min by credits, but Exhibit A caps music generation at **17 min/month**
  and downloads at **30 min/month**. The binding limit is the lower cap (17 min generation).
- Free tier: API Access = **No**; so a paid plan (Starter+) is required for `/v1/music`.
- Only Pro+ get high-quality downloads and 44.1kHz PCM API output; on Starter the practical
  output is standard MP3 (<=128 kbps).

### 2.3 Rights relevant to our use case
- Online explainer videos: covered by "all online and offline commercial use", which
  includes synchronizing Output in timed relation to audiovisual content (Media Rights),
  except film/TV/radio/Studio Games.
- Client projects: Media Rights are broad commercial use; no attribution required on
  Starter. Distribution of the rendered MP4 is permitted online/offline (not film/TV/radio).
- Rights after cancellation/downgrade (Music Terms Section 1.5): Output remains subject to
  the plan in effect when that Output was created; new Output uses the then-current plan.
  So tracks already generated on Starter keep Starter rights after cancellation. By
  contrast, the pricing FAQ says unused paid credits expire on downgrade/cancel.
- Offering generated music to users of our own app: constrained. Section 4.2 prohibits
  building or contributing to a "Music Library" (a collection of Output made available to
  third parties to use/license/download/incorporate), unless expressly authorized. Section
  4.3 prohibits "Model Resale". Starter eligibility is "For Individual Use Only". So:
  - Safe: generate music and embed it in videos we (or the account holder) produce.
  - Risky/needs legal sign-off: exposing a shared/browsable catalog of generated tracks to
    end users, letting users download standalone tracks as a library, or reselling access
    to the music model.
- Prohibited prompt inputs (Section 2.1): artist/stage names, songwriter names, song
  titles, album titles, publisher/label names, or distinctive lyric snippets. We are
  responsible for reviewing Output for clearance (Section 3.1).

### 2.4 Configuration gaps for TTS vs Music
- `ELEVENLABS_API_KEY` is reusable for music (same auth header), provided the plan has API
  access (Starter: yes).
- Missing: a music provider abstraction/registry, a music modality in the run policy, a
  music model env (default would be `music_v1`), and an output-format choice constrained
  to Starter-eligible formats (no 192kbps/PCM).

## 3. Proposed data model and asset workflow

### 3.1 Reuse, do not parallelize
Reuse `Asset` (type `music`) + `mediaMetadataReader` (duration) + the `assets/` store.
Add one writer mirroring `saveGeneratedAudio`:
- `mediaStore.saveGeneratedMusic(input)` -> `type: 'music'`, `provenance: 'generated'`,
  filename `music-<attemptId>.<ext>`, `generation: { generationId, provider, model, prompt }`,
  `metadata: { outputFormat, musicLengthMs, seed, providerRequestId, songId, license }`.
This is additive; no second asset system.

### 3.2 Project-level selection
Background music is a single, project-wide track (first phase). Add a small status-bearing
spec to the project so reuse/retry/recovery work like scene narration:
```
Project.music?: ProjectMusicSpec = {
  assetId?: string;
  prompt?: string;
  provider?: 'fake' | 'elevenlabs';
  model?: string;
  status: 'planned' | 'generating' | 'generated' | 'failed';
  seed?: number;
  musicLengthMs?: number;
  format?: string;
  duration?: number;
  lastAttemptId?: string;
  error?: string;
  updatedAt?: string;
}
```
- Normalized in `normalize-project.ts` (default absent/`planned`), owner of the selected
  track. `musicVolume` continues to live in `renderSettings.audio`.
- Minimal alternative if we want the smallest possible surface: store only
  `renderSettings.musicAssetId`. Trade-off: loses status/attempt/reuse-guard metadata and
  makes recovery harder. Recommendation: the small spec.

### 3.3 Reuse / cost control
- If `project.music.status === 'generated'` and `assetId` is available and the caller did
  not request regenerate -> return the existing track (HTTP 409 with reuse semantics,
  mirroring narration's `alreadyGenerated`) without a new paid request.
- Regenerate creates a new asset and attempt; old asset remains for reference.
- Selecting an imported `music` asset bypasses generation entirely (0 credits).

### 3.4 Workflow (as requested)
1. User enters a prompt (e.g. "calm corporate background, instrumental").
2. Request generates an instrumental track (`force_instrumental: true`) at a chosen
   `music_length_ms` (default e.g. 60s; looped at compose time for longer videos).
3. Audio is stored as a project `music` asset via `saveGeneratedMusic`.
4. Track is linked to the project (`project.music.assetId`); replacing selects another
   asset and marks the composition stale.
5. Volume via `renderSettings.audio.musicVolume` (already normalized/fingerprinted).
6. Re-render: only the composition stage re-runs; scene renders and scene narration are
   untouched because music lives at the project/composition level, not in scene
   fingerprints.

## 4. Composition and fingerprint design

### 4.1 Existing vs new
- Existing: per-scene normalize (narration volume applied), concat, output validation.
- New: a project-wide final music-mix pass, only when a music asset is selected.

### 4.2 Mix strategy (architecture)
Add a post-concat mix step in `LocalFFmpegVideoCompositor.compose()` / a new
`buildMusicMixArgs()`:
- Inputs: stitched video (`concat` output, already carrying narration) and the music file
  with `-stream_loop -1 -i music.<ext>` so short tracks cover the full duration.
- Filter graph (deterministic):
  `[1:a]volume=<musicVolume>,afade=t=in:st=0:d=<fadeIn>,afade=t=out:st=<total-fadeOut>:d=<fadeOut>,atrim=0:<totalDuration>[music];
   [0:a][music]amix=inputs=2:duration=first:dropout_transition=0[aout]`
  with `-map 0:v:0 -map [aout] -t <totalDuration>`.
- Narration volume stays per-scene (P15.1); only `musicVolume` is applied here. Avoids
  double-applying narration volume.
- Panning/limiting: keep it simple for phase 1 (fixed `musicVolume`, default 0.35) so
  music does not overpower speech. Advanced sidechain ducking is explicitly a later phase.
- Fades: deterministic fade-in (e.g. 1s) and fade-out (e.g. 2s), computed from
  `plan.totalDuration`.

### 4.3 Duration handling
- Music duration from `Asset.duration` (music-metadata).
- Shorter than video -> loop (`-stream_loop -1`) then `atrim`.
- Longer than video -> `atrim` to `totalDuration`.
- Missing/invalid/unreadable music asset -> reuse `assertAssetFile` behavior: clean error
  (`INCOMPOSITE_RENDER`/`RENDER_FILE_MISSING`) or, preferably, skip music with a warning so
  a render never fails solely on optional music. Decision needed (see Section 7).

### 4.4 Projects without music
- If no `musicAssetId`: keep the exact current concat path as the final output (no music
  mix pass). This guarantees unchanged, byte-for-byte-equivalent behavior for existing
  projects and keeps all current tests valid.

### 4.5 Fingerprint / staleness
- Extend `CompositionArtifact.inputFingerprint` with a `music` block:
  `{ assetId, volume, musicSignature }` where `musicSignature` covers assetId + duration +
  generationId/provider + prompt/model (enough to detect replacement/regeneration).
  `musicVolume` is already inside `audioMix`; the asset identity is the new part.
- Extend `deriveCompositionArtifactStatus()`: if a recorded music block differs from the
  current selection (or a music track was added/removed), mark `stale` with a clear reason.
- Do NOT add music to `createSceneRenderFingerprint()`: scene renders are video-only, so
  music changes must never trigger scene re-renders (consistent with P15.1).

## 5. Cost, rights, security, recovery risks

### 5.1 Cost / quota
- Music is billed per generation request: ~900 credits/minute on top of a separate
  music generation cap (Starter: 17 min/month). Downloads capped at 30 min/month on Starter.
- Risks: repeated regeneration burns credits and the monthly cap; long `music_length_ms`
  consumes the cap quickly; concurrency is only 2 on Starter.
- Mitigations: reuse guard (no implicit regeneration), default modest length + loop at
  compose, single project-level track, no per-scene music, explicit regenerate only.

### 5.2 Rights
- Confirm the "For Individual Use Only" eligibility and the "no Music Library / no Model
  Resale" constraints against the intended product surface. Embedding music in produced
  videos is permitted online; exposing a shared/browsable/downloadable track library to
  end users is not clearly permitted and needs written authorization.
- Enforce/document Music Terms Section 2.1 prohibited prompt inputs. We are responsible for
  reviewing Output for clearance (Section 3.1).
- Output generated during the active plan keeps that plan's rights after cancellation
  (Section 1.5), but unused credits expire on downgrade/cancel.
- Starter lacks high-quality downloads (no lossless/192kbps); request only standard MP3.

### 5.3 Security
- Credentials server-side only. The provider uses `xi-api-key` from
  `ELEVENLABS_API_KEY`; never expose it to the browser, logs, or generated files
  (mirror `elevenlabs-provider.ts`).
- Route the music modality through `resolveManualGenerationProvider('music', ...)` /
  the run policy: mock mode rejects real music providers before any paid request; real mode
  requires `ELEVENLABS_API_KEY` (P12 parity, no silent fallback).
- Validate responses: content-type `audio/*`, non-empty buffer, decodable duration;
  otherwise `MEDIA_INVALID`-style error. Honor timeouts/abort signals and map 401/403/429
  like the TTS provider.
- Never bypass P13/P14 run/auth architecture.

### 5.4 Reliability / recovery
- Interrupted project-level music generation must be reconciled on restart: extend
  `run-recovery.ts` (or a project-level reconciliation) so an active music generation with
  a usable asset is restored to `generated`, otherwise `failed`; in real mode suppress auto
  retry to avoid silent re-billing (same pattern as narration).
- Avoid duplicate paid generations: the reuse guard plus no implicit auto-retry.
- Idempotency: optional client-supplied request id to dedupe concurrent manual requests;
  at minimum a per-project music lock (like `activeNarrationLocks`).

## 6. Implementation steps, tests, acceptance criteria

### 6.1 Proposed first phase (P15.2)
1. Music provider abstraction: `lib/ai/music/{provider,registry,elevenlabs-provider,fake-provider}.ts`
   mirroring the TTS module. `MusicGenerationRequest { prompt, durationMs, model?, instrumental, seed?, outputFormat? }`,
   `MusicGenerationResult { provider, model, mimeType, format, data, duration, providerRequestId, songId?, metadata }`.
   ElevenLabs posts to `/v1/music` (JSON) with `force_instrumental`, `music_length_ms`,
   `model_id`, `seed`, `output_format` (Starter-safe MP3).
   Fake provider returns a deterministic short silent WAV for tests.
2. `media-store.saveGeneratedMusic()` (type `music`).
3. `lib/generation/music-service.ts` `generateProjectMusic(projectId, options)` mirroring
   `narration-service.ts`: policy-resolved provider, lock, reuse guard, regenerate, save,
   status transitions, error mapping.
4. Model: add `Project.music` spec + normalization + validation (optional asset existence).
5. Policy: extend `GenerationModality` and `RunProviderSelection` with `music`
   (`fake|elevenlabs`); defaults mock `fake` / real `elevenlabs`; preflight env
   `ELEVENLABS_API_KEY`; `assertRealProviderCredentials`. Keep single authority.
6. Composition: `resolveCompositionPlan()` resolves the selected music asset into the plan;
   `buildMusicMixArgs()` + a post-concat mix pass (skipped when no music); update
   `validateOutput` expectation for the music path.
7. Fingerprint/status: add `music` to `inputFingerprint` and to
   `deriveCompositionArtifactStatus`.
8. Recovery: handle `project.music.status === 'generating'` on restart.
9. API + minimal UI: `POST /api/projects/[id]/music` (generate/regenerate) and a way to
   select/replace/clear the track; surface `musicVolume`.

### 6.2 Later (out of P15.2)
- Sidechain/ducking, per-scene music, composition plans / section control, stems,
  streaming, inpainting, music as a production-run action type, richer music direction.

### 6.3 Tests
- Adapter: elevenlabs music request shape, error mapping (401/403/429/422), invalid
  response -> error; fake provider determinism. No paid calls.
- Registry + policy: mock rejects `elevenlabs` music; real requires `ELEVENLABS_API_KEY`
  (unit, mocked env).
- Service: reuse guard (no duplicate generation), regenerate, failure -> status `failed`,
  asset saved as `music` with correct metadata.
- media-store: saved filename/type/provenance/duration.
- Composition plan: music asset included when selected; absent otherwise; missing/invalid
  asset behavior.
- Compositor args: music mix graph (stream_loop, atrim, afade, volume, amix); no-music path
  unchanged (existing assertions stay green).
- Fingerprint/status: music add/replace/remove and `musicVolume` change -> `stale`;
  no music -> `current`; scene render status unaffected by music.
- Recovery: interrupted project music generation with/without usable asset; real-mode
  suppression.
- FFmpeg integration: gated on `ffmpeg` presence (as the existing integration tests).
  In this environment `ffmpeg`/`ffprobe` are not on PATH, so integration tests are skipped;
  unit/args tests run.

### 6.4 Acceptance criteria
- With no music selected, output and behavior are identical to today.
- Selecting/generating music produces a `music` asset, stored server-side, no key leakage.
- Mock mode cannot trigger a paid music request; real mode requires the key.
- Compose mixes music under narration at `musicVolume`, loops/trims/fades deterministically,
  and re-composes when the track or `musicVolume` changes without re-rendering scenes or
  regenerating narration.
- Interrupted music generation never causes a silent duplicate paid generation.
- typecheck, lint, and unit tests pass; FFmpeg integration tests pass where `ffmpeg` exists.

## 7. Decisions (resolved 2026-10-09)
1. Product surface vs rights: **embedded only.** Music is generated and mixed into produced
   videos; do NOT expose a shared/browsable/standalone-downloadable track library. This keeps
   us within Music Terms Exhibit A (no Music Library, no Model Resale).
2. Data model: **full `Project.music` spec** (Section 3.2), mirroring scene narration.
3. Trigger: **project-level manual action first.** `POST /api/projects/[id]/music`
   (generate/regenerate/select/clear) plus selection/replace/clear and `musicVolume`
   controls in the UI. A full `music_generate` production-run action type is deferred.
4. Automatable interface requirement: all music operations must be exposed as clean, typed,
   server-side actions behind the REST API so external automation can drive them later.
   This is a design constraint on the API/service surface only. It does NOT mean installing,
   starting, or connecting any third-party agent in this runtime; that remains out of scope
   and is not part of P15.2.
5. Defaults carried into implementation (still adjustable at build time): model `music_v1`,
   `force_instrumental: true`, Starter-safe MP3 (`mp3_44100_128`), default prompt-length
   ~60s looped/tile to project duration, deterministic fade-in 1s / fade-out 2s, fixed
   `musicVolume` (default 0.35) with sidechain ducking deferred.

Remaining minor builders' choices (not blocking): exact default `music_length_ms`, whether
fade durations are settings vs constants, and whether a client request id is added for
idempotency. These can be settled during implementation.
