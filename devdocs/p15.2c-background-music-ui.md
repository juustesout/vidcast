# P15.2c — Minimal background music generation UI

Adds a compact **Background music** section to the existing project workspace so a
user can generate one AI track through the P15.2b ElevenLabs integration and use
it as the composition soundtrack. No new provider architecture, no editor, no
playlists, no streaming.

## Recon

- The workspace (`components/project/project-workspace.tsx`) is a single client
  component with tabs `story | scenes | assets | references | generation`. Asset
  import/delete, narration generation and render actions all follow the same
  pattern: an `async` handler → `fetch` → parse `{ message, code, ... }` → on
  success `refreshProject()` (authoritative server state), plus a per-action
  message and a busy flag that disables the button.
- Per-scene generation (e.g. `runNarrationGeneration`) re-fetches the project
  after the call and shows the new asset through the existing asset list; the
  audio asset is previewed with `<audio controls src="/api/projects/<id>/assets/<assetId>/file">`.
- The music API already exists (`app/api/projects/[id]/music`): `GET` returns
  `{ music }`; `POST` supports `generate | regenerate | select | clear`. The
  service (`lib/generation/music-service.ts`) validates/clamps input, refuses a
  silent overwrite with `409 music.alreadyGenerated` unless `regenerate: true`,
  records the selection in `project.music`, and persists a normal `music` asset.
  Clearing only drops the reference; deletion protection for the selected asset
  lives server-side (`project:music` usage sentinel).
- Client-side there was no music UI. Styling/pattern conventions: `studio-panel`
  cards, `rounded-2xl` inputs, amber primary buttons.

**Placement:** the panel is rendered as the first section of the **Assets** tab
(the existing assets grid/aside stays untouched below it). This keeps the
background-music workflow next to the asset library it writes into and avoids a
new tab.

## Design

- New self-contained component `components/project/background-music-panel.tsx`,
  mounted from `project-workspace.tsx` with `project={draft}` and
  `onRefresh={refreshProject}`. Changes are applied server-side, then the parent
  re-fetches, so the existing project/asset update path (and composition
  staleness, volume, duration) keeps working unchanged.
- **Explicit action only.** The component has no `useEffect`/mount request. The
  provider is called only from the button's click handler.
- **Double-submit protection.** A `createSingleFlight()` guard plus a `disabled`
  button: a second click while a request is in flight is ignored. No automatic
  retries anywhere.
- **Form:** required prompt (`textarea`), optional duration in seconds (3–600,
  empty → existing length or 60 s default), instrumental checkbox (default on).
  Uses the server model/config defaults — no model picker. Validation happens
  client-side for fast feedback (`validateMusicForm`) and again server-side.
- **Result & selection:** after generation `refreshProject()` surfaces the new
  `music` asset in the existing Assets grid; the panel shows the current
  selection with an audio preview, a `Regenerate music` button (explicitly
  sending `regenerate: true`, with a note that the previous file is kept), a
  `Disable background music` button (`clear`, drops the reference only), and a
  dropdown to select any existing `music`/`audio` asset.
- **No silent overwrite:** generating while a selection exists always goes
  through the explicit `regenerate` path; the service still enforces the `409`
  contract.
- **Errors:** `describeMusicError` maps known codes (`music.provider.notConfigured`,
  `rateLimited`, `auth`, `rejected`, `failed`, `alreadyRunning`, `alreadyGenerated`,
  asset errors, …) and statuses to friendly messages. Raw keys/server internals
  are never rendered. On an uncertain outcome the UI reports it and does **not**
  retry.

## Tests

- Form validation & payload: prompt required/trimmed, duration 3–600 s,
  default/fallback duration, instrumental default and override.
- Explicit action / no auto-generation: the panel performs no request on render
  (no effect); the client is only invoked from handlers (covered structurally +
  client unit tests).
- Loading state and duplicate submissions: `createSingleFlight` runs the
  operation once; client sends exactly one `fetch`.
- Success registration/selection: generate/select client payloads and mapping.
- Errors and UI recovery: friendly mapping for 409/429/401/provider failures.
- Disable without asset deletion: `clear` action, message states the file is
  kept; no delete call.
- No generation on render/project load/other indirect actions: service/render
  layers already guarantee this; the panel adds no implicit call.

## Manual UI test

1. Set `ELEVENLABS_API_KEY` (and real mode) on the server, then open a project.
2. Go to the **Assets** tab → **Background music**.
3. Enter a prompt (e.g. "calm ambient piano"), leave duration empty (default
   60 s) or enter `15`, keep **Instrumental** checked.
4. Click **Generate music** once. The button shows `Generating...`; a second
   click is ignored. On success the message appears and the new `music` asset
   shows in the Assets grid.
5. Use the audio player to preview; click **Regenerate music** to replace it
   (previous file remains an asset), or **Disable background music** to clear
   the selection without deleting the file.
6. Select another music/audio asset from the dropdown and click
   **Use as background music**, then compose the final video to confirm the
   track is mixed in.

## Limits

- One project-wide track; no per-scene music, editor, or playlists.
- No model/provider picker by design; server defaults are used.
- No automatic retries on uncertain outcomes.
