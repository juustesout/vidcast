# P15.2a — Project-wide background music foundation

Status: implemented (mock/development generation only). Real ElevenLabs music
generation is intentionally **not** wired yet (P15.2b).

## Scope

Project-level background music on top of the existing asset / media / render
pipeline. No new dependencies, no credentials, no paid calls. The provider seam
mirrors the existing text-to-speech pattern so a real adapter can be added later
without touching the service, composition or API layers.

## What was added

- **Types** (`lib/types/render.ts`)
  - `ProjectMusicStatus`, `ProjectMusicGenerationAttempt`, `ProjectMusicSpec`,
    `Project.music?`.
  - `CompositionMusic`, `CompositionPlan.music?`.
  - `CompositionArtifact.inputFingerprint.music` (asset id, volume, fades,
    signature).
- **Provider seam** (`lib/ai/music/`)
  - `provider.ts`: provider-neutral request/result contract and typed
    `MusicProviderError`.
  - `fake-provider.ts`: deterministic silent PCM WAV whose duration matches the
    request.
  - `registry.ts`: `fake` only; the `elevenlabs` id throws `UNSUPPORTED` (501)
    by design.
- **Helpers** (`lib/render/music-mix.ts`): length clamping (3s–600s), music/audio
  asset detection, selection resolution, signature derivation, deterministic
  fades (1s in / 2s out).
- **Service** (`lib/generation/music-service.ts`): `generateProjectMusic`
  (lock, reuse guard, status transitions, asset persistence),
  `selectProjectMusic`, `clearProjectMusic` (drops the reference only; never
  deletes the asset).
- **Storage / project** (`lib/storage/media-store.ts`,
  `lib/projects/normalize-project.ts`, `lib/validation/project-validation.ts`):
  generated music assets, normalize/back-fill of `project.music`, validation of
  the selected asset.
- **Run policy** (`lib/production/run-policy.ts`, `run-types.ts`): `music`
  modality; mock default `fake`, real `elevenlabs`; real mode requires
  `ELEVENLABS_API_KEY`. Mock mode rejects real providers before any request is
  built.
- **Recovery** (`lib/production/run-recovery.ts`): an interrupted music
  generation is restored from an existing asset or marked failed (never stuck in
  `generating`).
- **Render** (`lib/render/video-composition-service.ts`,
  `video-compositor.ts`, `render-status.ts`): resolve the selected track into the
  plan, an optional post-concat music mix pass (skipped entirely when no track),
  and composition staleness when music/volume/fades change.
- **API** (`app/api/projects/[id]/music/route.ts`): get status / generate /
  regenerate / select / clear, with a dedicated throttle bucket.
- **Usage** (`lib/projects/usage.ts`): the selected music asset is reported as
  used so it cannot be deleted out from under the project.

## Render behavior

- No track selected → existing render path unchanged.
- Track selected → normalize per scene, concat, then a single music pass:
  `-stream_loop -1` → `volume` → `atrim` → fade in/out → `amix` with the concat
  audio (video copied, not re-encoded).
- Missing / invalid / unreadable music asset → the mix is skipped and the video
  still renders; the broken reference is surfaced by project validation.

## Defaults

- Model `music_v1`, `force_instrumental: true`, Starter-safe `mp3_44100_128`,
  ~60s looped, fade in 1s / fade out 2s, fixed `musicVolume` 0.35.
