# P40.3 - Presenter Production Readiness

## Verdict

P40.3 is implemented and verified locally. Paid presenter generation now fails closed
on missing or unmatched USD pricing and on an explicit per-generation USD cap. The
presenter end-of-scene gap is fixed by holding the final clip frame through the scene
end. Fullscreen and PiP compositions were re-rendered from the existing P40.2 pilot
clip without a new HeyGen request.

No paid request was made, and no commit or push was performed.

Publication of the pilot avatar remains **blocked** pending HeyGen confirmation of
stock-avatar commercial/likeness rights. See `docs/heygen-stock-avatar-licensing.md`.

## Implementation

### 1. USD cost guard and cost records

New `lib/presenter/pricing.ts` resolves a conservative estimate from:

- engine (`avatar_iii`, `avatar_iv`, `avatar_v`);
- avatar type (`photo_avatar`, `studio_avatar`, `digital_twin`, `custom_video`);
- output resolution (`720p`, `1080p`);
- scene duration and a configurable billing increment;
- operator-supplied `HEYGEN_PRICING_JSON`;
- project `presenter.maxCostUsd`.

The guard blocks with `presenter.cost.notConfigured` when pricing JSON, avatar type,
engine, rate, or `maxCostUsd` is missing or invalid. An estimate above `maxCostUsd`
blocks with `presenter.budget.exceeded`. These checks run before audio upload,
provider submission, or wallet reads, so a blocked request makes zero provider calls.

`HEYGEN_PRICING_JSON` example (the rate is illustrative, not a quoted tariff):

```json
{
  "billingIncrementSeconds": 1,
  "rates": [
    {
      "engine": "avatar_iii",
      "avatarType": "photo_avatar",
      "resolution": "1080p",
      "usdPerSecond": 0.0165
    }
  ]
}
```

The server ceiling is `$25` per generation. Authoring may lower it but not raise it.
The old seconds and paid-request guards remain in place.

Cost records are stored on the presenter attempt:

- `estimatedUsd`, `linearUsd`, `billableSeconds`, `usdPerSecond`, `maxCostUsd`;
- `walletBalanceBeforeUsd`;
- optional `observedUsd`, `observedAt`, `observedSource: "wallet_delta"`.

The wallet delta is measured around submit and again at completion if the first read
did not show a charge. It is supplementary accounting data, not a per-job invoice.
For the P40.2 input (3.578776 s at the example rate, 1 s increment) the estimate is
4 billable seconds = $0.066, rounded up to **$0.07**, matching the observed P40.2
wallet charge.

### 2. Scene-end timing

The previous placement ended at `min(sceneDuration, clipDuration)`. Because the
P40.2 clip is 3.50438 s and the scene is 3.6 s, the presenter disappeared for the
last ~96 ms and revealed the base scene.

`lib/render/video-composition-service.ts` now keeps the presenter placement enabled
for the full scene. `lib/render/presenter-overlay.ts` trims to the usable clip length
and clones the final frame with `tpad=stop_mode=clone` for the remainder. No narration
text, scene duration, or provider clip was changed.

If the padding exceeds 0.5 s, the composition plan emits a warning and still holds
the final frame. A start offset beyond the clip is skipped rather than rendering an
empty trim.

`COMPOSER_VERSION` was bumped from `p8` to `p9` so new overlay behavior is identifiable
in composition metadata.

### 3. Fullscreen, PiP, and audio

Both layouts use the existing overlay chain:

- fullscreen: scale-to-cover plus center crop;
- PiP: configured corner, width ratio, and margin, stacked over the base scene;
- output maps only `[baseVideo]` and `0:a?`;
- presenter clip audio is never mapped.

### 4. Publication rights

`docs/heygen-stock-avatar-licensing.md` records the Terms review:

- paid Creator/Pro/Business output is broadly licensed for commercial use;
- Free Plan output is non-commercial;
- no stock-avatar-specific licence or model-release grant was found;
- HeyGen disclaims third-party IP claims and places that risk on the user;
- the account's applicable plan is not proven by an API balance alone.

Therefore commercial YouTube publication is a blocker until HeyGen confirms the
specific stock avatar's rights in writing, or the presenter is replaced with a
consented custom/digital-twin avatar.

## Residual risks

- Pricing is operator-supplied. A stale or wrong `usdPerSecond` weakens the guard;
  there is no provider-side hard spend cap in the API call.
- Wallet delta can miss delayed charges or include concurrent account activity.
  `observedUsd` may remain absent if no decrease is visible.
- The USD ceiling is per attempt, not an aggregate project lifetime budget. The
  existing seconds and paid-request guards remain aggregate.
- The timing fix freezes the final frame. It removes the base-scene leak but does
  not create additional avatar motion. Mismatches over 0.5 s are warned, not blocked.
- The pilot hold is ~96 ms. Longer holds may be visually noticeable.
- Stock-avatar publication remains blocked; do not publish the pilot render.
- No authoring UI currently exposes `maxCostUsd`; projects needing real presenter
  generation must set it in project JSON/API data.
- The paid-plan clause must be matched to the actual HeyGen account plan.
