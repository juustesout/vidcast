# P15.2d — Fix rejected music generation after a mock-generated track

## Symptom

After generating a track in default (mock) mode, a later background-music
generation fails with **"The music request was rejected as invalid."** The UI
surfaces this from the `music.provider.unsupported` error code (HTTP 422).

## Root cause

`lib/generation/music-service.ts` derived the provider output format from the
*previously stored* music spec:

```ts
const outputFormat = options.outputFormat ?? existingMusic.format;
```

`ProjectMusicSpec.format` holds the resulting **asset** format (`"wav"` for the
mock `buildSilentWav()` output, `"mp3"` for real ElevenLabs). The background
music mock signature is a 8000 Hz mono 16-bit silent `RIFF/WAVE` file
(`lib/ai/music/fake-provider.ts`).

On the next generation the service forwarded that stored `"wav"` value as the
provider `output_format`, but `resolveOutputFormat` in
`lib/ai/music/elevenlabs-provider.ts` only accepts `mp3_*` codes, so it threw
`INVALID_REQUEST`, which mapped to `PROVIDER_REJECTED` → `music.provider.unsupported`
→ the "rejected as invalid" message. The stored value is an asset container name,
never a valid ElevenLabs codec code.

## Fix

- `lib/generation/music-service.ts`: only an **explicitly requested**
  `options.outputFormat` is forwarded; the stored `existingMusic.format` is no
  longer reused as a provider codec code.
- `lib/ai/music/elevenlabs-provider.ts`: `resolveOutputFormat` now maps
  short/legacy container names (`mp3`, `m4a`, `wav`, `auto`, `pcm`, `opus`) to the
  supported MP3 default instead of failing, so a stale/legacy value from any
  source (e.g. `ELEVENLABS_MUSIC_OUTPUT_FORMAT`) degrades gracefully.

## Tests

- `tests/music-service.test.ts`: new regression — regenerating over a project
  whose stored `music.format === 'wav'` sends **no** `outputFormat` to the
  provider (asserts the captured request's `outputFormat` is `undefined`).
- `tests/music-elevenlabs-provider.test.ts`: new case — `generate({ outputFormat: 'wav' })`
  succeeds, returns `format: 'mp3'`, and requests `mp3_44100_128`.

Mocked transport only; no real ElevenLabs calls.
