# P40.2 - Controlled HeyGen Avatar III Pilot

## Verdict

The controlled paid pilot completed with exactly one HeyGen request. The existing ElevenLabs narration produced a 1080p Avatar III photo-avatar clip, and that clip rendered successfully through the existing P40.1 compositor in both fullscreen and PiP layouts. No second paid request was made.

Observed wallet charge: **$0.07** (from $15.00 to $14.93). Remaining balance: **$14.93 USD**. Hard pilot cap: **$0.165**. The pilot is stopped for review; nothing was committed or pushed.

## Pilot Request

- Upload: `POST /v3/assets` with the existing narration MP3.
- Submit: `POST /v3/videos` with `type: avatar`, `engine.type: avatar_iii`, `resolution: 1080p`, `aspect_ratio: 16:9`, `output_format: mp4`.
- Avatar: public HeyGen photo avatar, id masked as `ee25...57d1`. No avatar was created.
- Input audio: existing ElevenLabs `eleven_multilingual_v2` narration, 3.578776 s, 44.1 kHz mono MP3. No TTS, translation, or new narration was generated.
- Provider job: `c34b678e6b66f15e34fe829e15380afc`.
- Attempts in the project: **1 generated attempt**, provider `heygen`. No retry or regeneration exists.

## Implementation

### 1. HeyGen v3 adapter correction

Updated `lib/ai/presenter/heygen-provider.ts` to match the confirmed v3 video schema:

- replaced the previous `dimension` field with `aspect_ratio` and `resolution`;
- added `engine: { type: 'avatar_iii' | 'avatar_iv' | 'avatar_v' }`;
- added `HEYGEN_PRESENTER_ENGINE` selection with `avatar_iv` as the backward-compatible default;
- maps output height to `1080p` or `720p`;
- surfaces `failure_code` and `failure_message` from status responses.

The request still uses the existing P40.1 upload, submit, status, and download flow. No second presenter pipeline was introduced.

### 2. Pilot project

A dedicated internal pilot project was created at `projects/project_e6e7461f-c049-4c3f-b441-e74cb0dd5ee2`:

- one text scene with the existing narration audio copied into the project;
- presenter enabled with provider `heygen`, one fullscreen scene setting, `maxGeneratedSeconds: 10`, and `maxPaidRequests: 1`;
- narration freshness validated as `current` before submission;
- project validation reported zero errors and zero warnings.

The scene duration was later set from 3.5788 s to 3.6 s because the scene render quantized to 3.567 s and composition rejected the 11.8 ms narration excess. This changed only local timing and did not trigger another provider request.

### 3. Composition layouts

The same generated clip was reused for both compositions:

- fullscreen: `renders/compositions/final-composition_37ae090d-e797-41a4-bcfd-0ba3f489d9c5.mp4`
- PiP bottom-right, width ratio 0.28, margin ratio 0.03: `renders/compositions/final-composition_091f1e11-b5cf-4d23-ad94-e8369aa30531.mp4`

Changing the layout changed `presenterSignature` and produced a separate composition without regenerating the avatar clip.

### Audio isolation

The final audio was compared with the original ElevenLabs narration:

- 48 kHz cross-correlation: **0.99834** at a 26.3 ms offset;
- RMS ratio final/narration: **0.993**;
- exactly one audio stream in each composition.

The overlay pass maps only base audio with `-map 0:a?`, so presenter audio is not included. The near-unity RMS ratio also shows no doubling from mixing the presenter track. The presenter clip's own audio is derived from the same narration, so correlation alone cannot distinguish a duplicate source; the tracked audio mapping and non-doubled level provide the isolation evidence.

### Lipsync

Sampled frames at 0.5 s, 1.5 s, and 2.5 s show visible mouth-shape changes while the avatar is speaking. This is a qualitative check only; no phoneme-level or forced-alignment measurement was performed.

### Regression and mock safety

- Full suite before the pilot: **122 files, 956 tests passed**.
- Presenter isolation tests rerun after the pilot: **12 tests passed** across `tests/presenter-service.test.ts` and `tests/presenter-heygen-provider.test.ts`.
- Mock mode has an explicit guard that rejects real-provider submission/polling and a test asserting no real provider call is made.

## Limitations and Residual Risks

1. The avatar is a public stock photo avatar, not a private avatar. Broadcast and commercial use depend on HeyGen's stock-avatar terms; this was approved for the pilot but should be confirmed before production use.
2. The generated clip is 3.50438 s while the scene is 3.6 s. The last ~96 ms therefore shows the base scene, not the presenter; fullscreen is not 100% coverage for this pilot.
3. Lipsync quality is only visually sampled, not objectively measured.
4. The observed $0.07 charge is higher than the per-second estimate of $0.0591. The billing increment or minimum charge is not documented; the wallet delta is authoritative.
5. The presenter spend guard is still seconds/request based, not USD based. A larger project or a more expensive engine could spend more than expected within the allowed seconds.
6. The pilot did not listen-test the final audio; verification used stream metadata, correlation, and RMS comparison.
