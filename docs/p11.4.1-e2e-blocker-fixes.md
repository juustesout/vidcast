# P11.4.1 E2E Blocker Fixes

## Scope
This document covers targeted fixes for the two live P11.4 blockers:
1. Mock image decode/render failure during live MCP stdio run.
2. Missing-credential fail-closed proof through MCP stdio.

All changes keep the P11.3 architecture intact (policy locking before execution, no implicit provider fallback, read-only MCP contracts unchanged, production tools still isolated from read-only tools).

## Root Cause 1: Mock Image Failure

### Symptom
Live run logs showed scene render failure after successful mock image generation, with FFmpeg decode errors:
- inflate returned error -3
- Decoding error: Generic error in an external library

### Actual Cause
The fake image provider emitted a tiny hard-coded base64 PNG fixture that decoded in sharp but was not reliably decodable by FFmpeg/libpng in this runtime.

### Fix
Changed fake image generation to produce deterministic PNG bytes via sharp create+png, using a prompt-derived color hash.
- This preserves deterministic mock behavior.
- Output is a valid, FFmpeg-compatible PNG.
- Renderer validation was not weakened.

File changed:
- lib/ai/image-generation/fake-provider.ts

### Regression Evidence
Added test proving provider output can be rendered by the existing LocalFFmpegRenderer:
- tests/fake-image-provider-render.test.ts

This test writes the fake PNG to disk, builds a normal render plan, runs renderer.render, and asserts completed MP4 output.

## Root Cause 2: Credential Preflight Discrepancy

### Symptom
Previous probe reported accepted real-mode run instead of expected fail-closed credential rejection.

### Actual Causes
1. Probe environment was not truly isolated from ambient runtime configuration.
2. MCP error mapping collapsed specific provider configuration failures into POLICY_DENIED, hiding the precise preflight failure class.

### Fixes
1. Added an isolated child-process harness server with sanitized environment:
- Explicitly removes OPENAI_API_KEY and ELEVENLABS_API_KEY.
- Uses HeadlessProductionRunService with allowRealProviders=true and mode=real.
- Exposes debug endpoint showing credential presence flags and runBatch execution count.
- Ensures preflight can be validated independently from ambient app env.

File added:
- scripts/p11.4.1-credential-harness-server.ts

2. Added MCP stdio integration test for fail-closed behavior:
- Starts harness process.
- Creates a project on harness API.
- Calls run_production over MCP stdio in real mode with real providers.
- Asserts PROVIDER_NOT_CONFIGURED and zero production action execution.

File added:
- tests/mcp-credential-failclosed-stdio.integration.test.ts

3. Preserved specific provider error classification through service/client mapping:
- Run service now forwards PROVIDER_NOT_CONFIGURED as a distinct error code.
- MCP production types now include PROVIDER_NOT_CONFIGURED.
- API client mapping now preserves explicit PROVIDER_NOT_CONFIGURED instead of collapsing to POLICY_DENIED.

Files changed:
- lib/production/run-service.ts
- mcp/production/types.ts
- mcp/production/api-client.ts
