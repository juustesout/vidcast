## Findings

### Confirmed
1. MCP stdio transport path is real and functioning
- Verified by automated integration test using MCP Client + StdioClientTransport against local stdio server.
- Verified again by live script calling run_production, get_run_status, and get_run_log through stdio.

2. Tool registration and exposure are correct
- Live tool listing includes both read-only and production tools, including run_production, get_run_status, and get_run_log.

3. Duplicate-start reuse works
- duplicateReused = true in live script output.

4. Log pagination works
- Live script fetched page 1 and page 2 with non-zero counts and hasMore true after page 2.

5. Policy denial when real mode is not allowed works
- realModeRejectedCode = POLICY_DENIED when calling mode=real on the baseline server with PRODUCTION_RUN_ALLOW_REAL_PROVIDERS=false.

### Reproducible Issues Observed
1. Baseline mock lifecycle does not complete successfully in this environment
- finalSuccessStatus is failed (expected completed for happy path scenario).
- Run log evidence:
  - action_completed: Scene image generation completed
  - action_failed: Scene render failed: FFmpeg failed while rendering the scene
  - run_stopped_unresolved: Production run stopped with unresolved actions
- Additional FFmpeg stderr evidence showed repeated PNG decode errors (inflate returned error -3), indicating invalid/corrupted scene image input for render.

2. Missing-credentials fail-closed preflight could not be demonstrated as rejecting in this runtime setup
- Probe result reports UNEXPECTED_SUCCESS.
- Direct API probes to the opt-in server also returned 202 Accepted for mode=real with openai/elevenlabs providers.
- This means the expected PROVIDER_NOT_CONFIGURED rejection was not observed in the live environment.
